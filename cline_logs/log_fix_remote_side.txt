3. ARCHITECTURE & DATABASE DESIGN
================================================================================

CORE DESIGN PRINCIPLES:
- Async SQLAlchemy 2.0 throughout
- UUID primary keys on all tables
- S3-compatible storage for all media (videos, thumbnails)
- Soft deletes where appropriate (is_deleted flags)
- Role-based access control (user/moderator/admin)
- Presigned URLs for temporary media access (1 hour default)

DATABASE TABLES (8 total):

1. users
   - id: UUID PK
   - email: String(255) UNIQUE, index
   - username: String(50) UNIQUE, index
   - password_hash: String(255)
   - role: Enum(user/moderator/admin), default=user
   - is_active: Boolean, default=True
   - is_verified: Boolean, default=False
   - avatar_url: String(500), nullable
   - bio: Text, nullable
   - last_login_at: DateTime, nullable

   RELATIONSHIPS:
   - videos (one-to-many, author)
   - comments (one-to-many)
   - reactions (one-to-many)
   - subscriptions_as_subscriber (one-to-many)
   - subscriptions_as_channel (one-to-many)
   - complaints_reported (one-to-many, reporter)
   - complaints_reviewed (one-to-many, moderator)
   - moderation_logs (one-to-many)

2. videos
   - id: UUID PK
   - author_id: UUID FK→users (ondelete=CASCADE, index)
   - title: String(200), not null
   - description: Text, nullable
   - original_s3_key: String(500), not null
   - thumbnail_s3_key: String(500), nullable
   - duration_seconds: Integer, nullable
   - views_count: Integer, default=0
   - status: Enum(draft/processing/ready/rejected/deleted),
             default=draft, index
   - visibility: Enum(public/unlisted/private), default=public, index
   - published_at: DateTime, nullable

KEY DESIGN DECISIONS:
- Soft deletes: comments have is_deleted; videos use status flags
- Polymorphic reactions: target_type+target_id for videos/comments
- Dual subscription: same table, subscriber vs channel both reference users
- Complaint workflow: pending→reviewed→resolved/rejected
- Moderation logs separate from complaints (tracks actions taken)
- S3: all media via presigned URLs, keys stored in DB
- UUID throughout for sharding friendliness
- Role-based access enforced in API routes (mod/min/admin checks)
- REACTIONS: toggle like/dislike on videos
- SUBSCRIPTIONS: subscribe/unsubscribe/check status
- MODERATION: create complaints, hide videos (mod/admin only)

CORE UTILITIES:
- config.py: Pydantic Settings with DB URL, S3 credentials, JWT config
- security.py: bcrypt password hashing, JWT create/decode (HS256)
- s3.py: Full MinIO/S3 integration - bucket ensure, upload, delete,
  presigned URLs (1hr expiry)
- session.py: Async engine, sessionmaker, get_async_session dependency
